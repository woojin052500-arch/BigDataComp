# 데이터 인벤토리 — 하수관로

최초 확인 2026-09-03 · **재검토 후 정정 2026-09-03**

## 정정 이력

1차 보고에서 "부산의 관로 관련 데이터는 존재하지 않는다"고 결론지었다. **이는 과잉 일반화였고 틀렸다.**
data.go.kr에서 `하수관로` 키워드로만 검색했기 때문에, 제목에 그 단어가 없는
`부산광역시_도시공간정보시스템_도로상하수도기반시설물_하수맨홀`(15084501)을 놓쳤다.
이 자료에는 설치일자와 행정동이 들어 있어 노후도 변수를 만들 수 있다.

작업분해에 적힌 3개 소스에 대한 판정 자체는 유지된다. 틀린 것은 그 3개를 넘어선 일반화였다.

### Q1. 부산 레코드가 있는가 → 예

①의 미리보기에서 부산 레코드를 직접 확인했다. 미리보기에 노출된 범위에서
**12개 구·군, 20행**을 실측했다.

중구, 서구, 동구, 영도구, 부산진구, 동래구, 남구, 북구,
해운대구(수영·해운대·동부 3행), 사하구, 금정구, 강서구(7행)

미리보기가 강서구에서 절단되어 연제구·수영구·사상구·기장군 4개는 확인하지 못했다.
"16개 구·군 전부"라고 단정할 근거는 없다. 전체 파일은 7,110행.

### Q2. 설치연도와 관경 컬럼이 있는가 → 아니오

①의 컬럼 정의서 25개 항목 전체를 확인했다. 설치연도도 관경도 없다.

- 위치: 시도, 구군, 행정구역명, 하수처리장명
- 시설: 하수처리 시설용량
- 면적: 처리구역면적 합계/합류식/분류식, 분류식화율
- 배수설비(개소): 합계, 합류식, 분류식합계, 분류식연결, 분류식미연결
- 관로 **연장(m)**: 총시설연장, 차집_오수간선합계, 차집, 오수간선, 지선합계,
  지선합류식, 지선분류식우수, 지선분류식오수
- 부속시설(개소): 합류식우수토실, 분류식우수토실, 분류식우수토구

관로에 대해 주어지는 값은 길이(m)뿐이다.

②는 컬럼 이전에 규모에서 배제된다. 전체 행이 1행이고 "시도별 하수관로 시설현황"이다.

### Q3. 공간 단위가 관로별인가 행정동별인가 → 기타

**둘 다 아니다. `시도 / 구군 / 하수처리장` 단위다.**

위치 컬럼 4개 중 `행정구역명`은 행정동이 아니라 구·군명을 반복한 값이다.
미리보기에서 `서울특별시 / 종로구 / 종로구`, `부산광역시 / 중구 / 중구`,
`부산광역시 / 부산진구 / 부산진구`로 구군 컬럼과 동일하게 채워져 있다.

한 행이 가리키는 범위는 "어느 구·군의, 어느 하수처리장 처리구역"이다.
페이지 유의사항에 "지자체 행정구역 특성에 따라 B열(구·군)은 공백일 수 있습니다"라고
적혀 있으나, 부산은 구·군 체계이므로 해당하지 않는다.

②는 시도 단위이므로 부산 전체가 1행이다.

### 하수관로 라인 레이어는 개방돼 있지 않다

부산 Big-데이터웨이브에서 `도시공간정보시스템` 시리즈를 조회한 결과, 개방된 하수도
시설물은 **하수맨홀(점)과 유량계**뿐이다. 관로 라인 레이어는 목록에 없다.
`지형지물부호코드 현황`에 하수관로·하수맨홀·배수설비관 코드가 정의돼 있어
시스템 내부에는 존재하나, 개방된 것은 코드값 목록이다.

## 분석 단위에 대한 결론

작업분해의 "이 답이 분석 단위를 결정한다"에 대한 답.

- 작업분해 지정 3개 소스만으로는 구·군 단위가 최대이고, 도로 구간도 100m 격자도 성립하지 않는다.
- 하수맨홀 자료를 쓰면 **행정동 단위(부산 약 200개)**까지 올라간다.
  기획서 v3 5.1이 상정한 후퇴 조건("행정동 단위로만 집계돼 있으면")에 정확히 해당한다.
- 도로 구간 단위로 관로 노후도를 붙이려면 행정동 값을 그 안의 구간에 균일하게 깔아야 한다.
  구·군보다는 훨씬 낫지만 여전히 구간 사이 변별력은 행정동 경계에서만 생긴다.
